## Что остаётся неизвестным по предметной области

Вопросы участников №650, 689, 702, 703 не считаем официальными ответами. В прочитанных сообщениях нет однозначного регламента исправления исходной карточки ДДС, доступа к записи первоначального обращения, полной матрицы полномочий каждой службы и длительности реального занятия.

Поэтому исходная карточка ДДС остаётся неизменной. Обучаемый записывает обнаруженную проблему и способ уточнения; содержание этой записи оценивает преподаватель. Противоречие адреса в новом демосценарии видно из самой карточки — для его обнаружения не требуется недоступная аудиозапись.

## Реализовано в этой доработке

1. **Занятие:** подготовка преподавателем, выбор учеников, нескольких опубликованных билетов и категорий, тренировка/экзамен, случайный порядок для каждого ученика, общий запуск и остановка. При остановке незавершённые попытки сохраняются и оцениваются в текущем состоянии. Продолжение идёт по зафиксированной последовательности; завершённые карточки нельзя повторно открывать как новые внутри занятия. После последней карточки ученик ждёт завершения преподавателем. Число карточек конечно, не бесконечная генерация.
2. **Наблюдение:** видны прогресс и попытки участников занятия; можно открыть карточку и историю действий. Преподаватель видит свои занятия и группы.
3. **ДДС:** все службы-получатели, собственные статусы, запись проверки, выбор абонента, исходящее текстовое сообщение, первый и последующие подготовленные ответы. Разговор не меняет статусы автоматически. Нет вызовов реальным службам.
4. **Редактор:** администратор и преподаватель создают билеты; преподаватель редактирует свои, чужие копирует. Публикация проверяет ссылки критериев и контактов. Версии и снимки попыток сохраняются.
5. **Повторное использование карточки ученика:** завершённая карточка 112 превращается в черновик задания ДДС с указанием источника. Преподаватель дополняет контакты и эталон, затем публикует. Такие билеты можно смешивать с авторскими в одном занятии. Автоматического утверждения ученической карточки нет.
6. **Перенос билетов:** импорт JSON через существующую схему валидации и экспорт JSON. Аудиофайлы этим экспортом не упаковываются: в JSON остаются их идентификаторы. Это не интеграция с продуктивной Системой-112.
7. **Отчёт:** CSV с попыткой, учеником, временем, нормативом, отклонением, баллом и подробными критериями. Доступ ограничен той же областью, что результаты. Значения защищены от выполнения формул при открытии в табличной программе.
8. **Материалы:** преподаватель/администратор создаёт текст или загружает TXT/MD для конкретной группы. Ученики других групп не имеют доступа. PDF/DOCX как вложения пока не реализованы.
9. **Реестр:** карточки, адреса, описания, службы, состояния; поиск и фильтрация 112/ДДС/состояние. Открытие сохранённой попытки.
10. **Устойчивость ввода:** локальный черновик карточки 112 с явным восстановлением после перезагрузки. Ключ включает пользователя и попытку. Серверные данные и ревизии остаются источником истины. Это не полная офлайн-очередь всех действий.
11. **Контроль текста:** осторожные локальные проверки повторов слов/знаков и смешения алфавитов. Они выводят замечания, не дают автоматическую оценку смыслу и не называются нейросетью.
12. **Демонстрация:** отдельный новый билет «ДДС · взаимодействие с бригадой и проверка карточки». Старые билеты, результаты и версии не перезаписаны.

## Как определяется правильность

Правильность не выводится автоматически из названия происшествия. Автор утверждает эталон и рубрику. Поля сравниваются с нормализацией, списки — по составу; вопросы, службы, статусы и факт связи — по журналу действий; время — по серверным отметкам. Наличие связи само по себе не означает правильное содержание разговора.

Свободное описание, обоснование отказа, замечание к входящей карточке и содержание передачи информации требуют экспертной проверки. До неё итог помечен предварительным. Преподаватель может изменить результат критерия только с комментарием; сохраняются история и аудит. Администратору запрещено менять оценки внутри активного занятия.

Для ДДС норматив времени относится к первичному решению, а не ко всей длительности аварийных работ. В отчёте различаются общая продолжительность попытки и измерение, сопоставляемое нормативу. Новый норматив по умолчанию — 30 секунд; автор может его изменить. Уже опубликованные учебные нормативы не переписывались.

## Архитектурные изменения

Стек сохранён: React + TypeScript + Vite, FastAPI/Pydantic, SQLAlchemy/Alembic, PostgreSQL. SQLite используется в изолированных интеграционных тестах. Зависимостей от облака в выполнении заданий нет.

| Файл / модуль | Ответственность |
|---|---|
| `apps/api/app/extensions.py` | Жизненный цикл занятий, последовательность карточек, отчёты, материалы, реестр, повторное использование |
| `apps/api/app/schemas.py` | Валидация контактов и новых команд/критериев |
| `apps/api/app/main.py` | Команды проверки и связи, права автора билета, защита эталонов |
| `apps/api/app/domain.py` | Новые критерии, измерение времени, замечания к тексту |
| `apps/api/app/seed_workflow.py` | Идемпотентное добавление отдельного демобилета |
| `apps/api/migrations/versions/0002_lessons.py` | Таблица занятий, связь назначений с занятием |
| `apps/api/migrations/versions/0003_materials.py` | Учебные материалы с областью доступа по группе |
| `apps/web/src/lessons.tsx` | Подготовка, мониторинг, запуск и остановка занятия |
| `apps/web/src/library.tsx` | Справочная база и реестр карточек |
| `apps/web/src/workspace.tsx` | Проверка карточки, связь ДДС, восстановление черновика |
| `apps/web/src/tickets.tsx` | Редактор контактов, импорт/экспорт, права преподавателя |

Занятие сохраняет частные неизменяемые версии выбранных задач с индивидуальным порядком. Команда ученика и остановка преподавателем сериализуются блокировкой занятия в PostgreSQL. Повторные команды определяются по command_id. Версия задания не меняется задним числом. Исходные карточки и текст взаимодействия сохраняются для разбора.

## Не закрытые требования окончательного ТЗ

Нельзя заявлять полное соответствие всему официальному ТЗ. Ниже реальные ограничения, а не скрытые выполненные пункты:

- Голос, SIP/VoIP и VR отложены пользователем.
- Нейросетевая генерация сценариев, смысловая оценка и ML-прогноз компетенций не подключены. Локальные правила и статистика не заменяют их.
- Нет официально размеченного полного банка эталонов и полного маршрутизатора по территории/подчинённости; демонстрационные сценарии требуют методической валидации.
- Полная грамматическая проверка русского текста не реализована.
- Встроенного администрирования служб ОС, LDAP/AD и многофакторной аутентификации нет.
- Работающий демонстрационный адрес использует HTTP. TLS, доверенные сертификаты внутри учебной сети и политика ежедневного резервирования требуют отдельной настройки развёртывания; наличие скрипта резервирования не означает настроенный ежедневный запуск.
- Требования 100 пользователей / 20 одновременных занятий, 100 записей/сек, восстановление после сетевого разрыва и отказоустойчивый кластер пока не подтверждены полноценными нагрузочными/аварийными испытаниями.
- Локальный черновик защищает ввод карточки 112; не реализована универсальная офлайн-очередь всех команд и сообщений ДДС.
- Экспорт XLSX/PDF, вложения PDF/DOCX к материалам, пакетный архив с медиа и точное пиксельное воспроизведение всех окон АРМ не завершены.

Эти пункты нужно учитывать в заявке и презентации, не называя текущую версию полностью соответствующей ТЗ.
