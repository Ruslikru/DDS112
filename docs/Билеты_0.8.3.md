# Создание билетов — версия 0.8.3

## Что изменено

- Синяя кнопка запускает ИИ-мастер; обычная — ручное создание.
- Увеличены подписи кнопок, добавлен отступ перед галочкой о животных.
- Клик на фон не закрывает мастер. Крестик и Escape требуют подтверждения сброса.
- Район больше не вводится вручную. Генерация выбирает московские улицу, район и округ; эта география указана в настройках ИИ.
- Телефон, ФИО, адресные детали и признаки используются согласованно в карточке, ответах заявителя и контактах. Для ситуаций в доме добавляются подъезд, этаж и домофон. Неприменимые поля остаются пустыми.
- Пострадавшие люди добавляют скорую. Признаки пожара, ДТП и газа подбирают действующие службы. Газовая добавляется только при наличии в справочнике. Отрицания вроде «дом не газифицирован» не являются основанием для её добавления. Правила администратора имеют приоритет над подбором по тегам.
- В режиме 112 подбор работает при изменении типа, признаков и сведений о пострадавших. Оповещение подтверждается учеником.
- Название включает конкретное обстоятельство и улицу. Локальная модель получает основу ситуации, чтобы уменьшить бессодержательные формулировки.
- Проверка оформления больше не считает отсутствие слова в частотном словаре доказательством опечатки. Проверяются повторы, смешение алфавитов, лишние знаки и известные опечатки. Полную грамматику и содержание проверяет преподаватель.
- Убран источник сценария и настройка озвучки из редактора; данные существующих билетов сохраняются.
- Новый билет содержит одно задание. Старые билеты с несколькими заданиями сохраняют переключатель между ними.
- Сообщения бригады оформлены отдельными блоками с многострочным текстом. Новое сообщение по умолчанию — звонок.
- В проверке: имена абонентов и вопросы вместо ID, ползунок значимости, большие поля текста. Выбор поля карточки показывается только для проверки её значения. Навык скрыт из редактора, но сохранён в данных для статистики.

## Проверки

- Сборка TypeScript/Vite.
- 60 серверных тестов; отдельная повторная проверка маршрутизации животных.
- Создание, сохранение и публикация черновиков 112 и ДДС, подбор скорой и газовой, отрицания и правила администратора.
- Генерация с настоящей локальной Qwen3 0.6B.
- Визуальная проверка мастера, сообщений бригады и критериев в браузере; подтверждение закрытия и сохранение окна при клике на фон.
- Самопроверка собранного EXE 0.8.3: WebView2, API, локальная модель, сохранение данных при перезапуске и стартовая резервная копия — успешно.

Многокомпьютерная установка обновления в физической локальной сети не проверялась. Смысл произвольных историй модели требует проверки преподавателем перед публикацией.

## Основа примеров

Состав карточки сверялся с приложенными сканами билетов 2 и 3: обстоятельства, адрес, подъезд, этаж, домофон, заявитель и сведения о пострадавших. Личные данные из PDF не копируются в генерируемые карточки.

Связи улиц и районов взяты из опубликованных городских перечней:

- [Адресный перечень Москвы](https://www.mos.ru/upload/documents/oiv/prilojenie_2_2%281%29.pdf).
- [Перечень Департамента транспорта](https://parking.mos.ru/upload/iblock/27f/gdmicqchuoiydjitk92fml55sremdl4m.pdf).
- [Объекты района Отрадное](https://gp166.mos.ru/news/SergeySobyaninoznakomilsyaskhodomrealizatsiiprogrammyMoyrayonvOtradnom/).

Справочник сейчас содержит пять улиц в четырёх районах. Номера домов, внутренние адресные детали, заявители и телефоны создаются как факты учебной ситуации.

## Запуск

Запускайте `Dispetcher112.exe` из папки версии 0.8.3 вместе с находящимися рядом `_internal` и `local_ai`. ZIP обновления для этой версии не предоставляется.
