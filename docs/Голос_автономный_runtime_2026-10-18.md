# Голосовые сообщения перестали генерироваться: зависимость от диска F:

Дата: 18 октября 2026 года. Версия приложения: 0.8.20.

## Симптом

В установленном приложении (режим «Запустить на одном ПК») индикатор
«Генерируются голосовые сообщения» остановился на **21/127** и больше не менялся.
Озвучка реплик, новых приветствий и распознавание речи не работали.

21 «готовое» сообщение — это записи, заранее положенные в комплект
(`local_ai/voice/builtin`). Ни одно сообщение, которое нужно было синтезировать,
так и не было создано.

## Диагностика

1. В `server.log` повторялась ошибка моста голоса:
   `RuntimeError: Голосовой движок остановился. Подробности в voice-runtime.log.`
2. В `voice-runtime.log` текущего запуска (`%LOCALAPPDATA%\Dispetcher112\demo\runs\<id>\`)
   одна и та же ошибка на каждое задание очереди: процесс падает сразу при запуске,
   и задание помечается как `failed`:

   ```
   File "...\Dispetcher112\local_ai\voice_worker.py", line 8, in <module>
       import numpy as np
   ModuleNotFoundError: No module named 'numpy'
   ```

3. Голосовой процесс запускается отдельным встроенным Python:
   `local_ai\voice\runtime\python.exe` (см. `VoiceRuntime.call` в `local_ai/voice.py`).
   В его `Lib\site-packages` было около 20 пакетов (faster_whisper, av, ctranslate2…),
   но **не было** numpy, torch, torchaudio, soundfile и qwen-tts.
4. Там же лежал файл `qwen_runtime.pth` с одной строкой:

   ```
   F:/AI/Qwen3-TTS/.venv/Lib/site-packages
   ```

   На этом ПК диска F: нет.

## Причина

Это ошибка упаковки, а не кода приложения.

Файлы `*.pth` в `site-packages` Python читает при запуске и добавляет записанные
в них пути к списку поиска модулей. Встроенный голосовой Python собрали так, что
тяжёлые библиотеки (torch с CUDA — несколько гигабайт) не установили в комплект,
а подключили одной строкой из готового виртуального окружения Qwen3-TTS
на компьютере разработчика (`F:\AI\Qwen3-TTS\.venv`).

- На ПК разработчика путь существует, поэтому всё работало, в том числе
  самопроверка `desktop_launcher.py`.
- `scripts/build-portable.ps1` и `packaging/installer.iss` копируют
  `local_ai\voice\runtime` целиком, вместе с `.pth`, и ничего не проверяют.
- Папка `local_ai/voice/runtime` не хранится в git, поэтому в репозитории
  ошибку не было видно.

Если пути из `.pth` нет, Python молча его пропускает, и ошибка появляется только
при первом `import numpy`. Поэтому на **любом** ПК без `F:\AI\Qwen3-TTS` голос
не работает целиком: синтез Qwen3-TTS и Silero, а также распознавание Whisper
(`voice_worker.py` импортирует numpy и torch в самом начале).

При разборе нашлись ещё две проблемы того же комплекта:

- В `site-packages` смешаны файлы двух версий pip (`pip-24.0.dist-info` и
  `pip-26.1.2.dist-info`). pip падал с
  `ImportError: cannot import name 'RequirementInformation'`.
- Интерпретатор — копия Python, установленного через uv, с маркером
  `Lib\EXTERNALLY-MANAGED` (PEP 668). pip и ensurepip отказываются ставить в него
  пакеты (`externally-managed-environment`).

## Решение

### В исходном коде (для следующих сборок)

| Файл | Что сделано |
| --- | --- |
| `scripts/check_voice_runtime.py` (новый) | Запускается встроенным голосовым Python. Завершается ошибкой, если какой-либо `.pth` или элемент `sys.path` указывает за пределы комплекта, а также если не импортируется или загружается извне любой из модулей `numpy`, `torch`, `torchaudio`, `soundfile`, `qwen_tts`, `faster_whisper`. |
| `scripts/prepare-voice-runtime.ps1` (новый) | Делает голосовой runtime автономным: удаляет `.pth` с внешними путями, переустанавливает pip через `ensurepip`, ставит пакеты из `local_ai/voice-requirements.lock.txt` прямо в `site-packages` комплекта (torch cu128 — с `download.pytorch.org`) и запускает проверку. На время установки маркер `EXTERNALLY-MANAGED` переименовывается и затем возвращается на место. Параметр `-Runtime` позволяет починить уже установленную копию. |
| `scripts/build-windows.ps1` | Перед компиляцией установщика запускает `check_voice_runtime.py`. Если runtime зависит от внешних путей, сборка останавливается с подсказкой запустить `prepare-voice-runtime.ps1`. |
| `scripts/build-portable.ps1` | Та же проверка на уже скопированной переносной папке, до упаковки в 7z. |

Теперь собрать установщик с такой ошибкой нельзя. На ПК разработчика проверка
тоже срабатывает: путь на F: там существует, но выходит за пределы комплекта.

Порядок сборки:

```powershell
.\scripts\prepare-voice-runtime.ps1   # один раз после обновления local_ai/voice/runtime
.\scripts\build-windows.ps1
```

### На этом ПК (установленная версия 0.8.20)

Встроенный runtime в `%LOCALAPPDATA%\Programs\Dispetcher112\local_ai\voice\runtime`
починен той же командой:

```powershell
.\scripts\prepare-voice-runtime.ps1 -Runtime "$env:LOCALAPPDATA\Programs\Dispetcher112\local_ai\voice\runtime"
```

Приложение переустанавливать не нужно. Упавшие задания очередь сама не повторяет
(статус `failed`), поэтому:

- в режиме «Запустить на одном ПК» достаточно перезапустить приложение: каждый запуск
  создаёт новую учебную базу, и задания генерируются заново;
- на учебном сервере у каждого упавшего сообщения в панели очереди есть кнопка
  «Повторить».

## Проверка

Проверено 18 октября 2026 года на этом ПК (RTX 4060 Ti):

- До исправления `check_voice_runtime.py` на установленной копии завершался
  ошибкой и указывал на `qwen_runtime.pth: path outside the runtime:
  F:/AI/Qwen3-TTS/.venv/Lib/site-packages` и на отсутствие numpy, torch,
  torchaudio, soundfile, qwen_tts. faster_whisper тоже не загружался, потому что
  ему нужен numpy.
- В базе текущего запуска было 21 задание `ready` (готовые записи из комплекта)
  и 106 `failed` с ошибкой «Голосовой движок остановился».
- После `prepare-voice-runtime.ps1`: `Voice runtime is self-contained`.
- Через `VoiceRuntime` (тот же код, что использует сервер) на установленном
  комплекте:
  - Silero, CPU: 3,3 с речи за 0,9 с;
  - Qwen3-TTS, GPU: 3,44 с речи за 16,2 с;
  - Whisper распознал результат: «Брегада прибыла на место. Преступаем к работе.»
- При загрузке qwen-tts в лог пишутся предупреждения `SoX could not be found!`
  и `flash-attn is not installed`. На синтез они не влияют.

Повторную генерацию 106 заданий в интерфейсе приложения после перезапуска
не проверял.

## Что осталось

- **Перевыпустить установщик и переносную версию.** Хакатонная сборка
  на Яндекс.Диске собрана теми же скриптами из той же папки и, скорее всего,
  содержит тот же `qwen_runtime.pth`. Тогда у проверяющих голос не заработает.
  Нужно на ПК сборки запустить `prepare-voice-runtime.ps1`, затем
  `build-windows.ps1` / `build-portable.ps1` и заменить файлы по ссылке.
- Размер комплекта вырастет на объём torch, torchaudio и библиотек CUDA
  (несколько гигабайт). Если это критично, отдельно стоит рассмотреть вариант
  torch для CPU.
- Когда голосовой движок недоступен целиком, все задания по очереди падают,
  и повторять их приходится по одному («Повторить» у каждой записи). Стоит
  добавить кнопку «Повторить все» и показывать администратору общую причину
  (например, «Голосовой модуль не запускается, см. voice-runtime.log»), а не
  ошибку в каждой строке.
