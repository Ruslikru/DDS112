# ИИ-ассистент преподавателя — состояние работ

Дата: 18 октября 2026 года. Ветка `claude/affectionate-hofstadter-0074b3`, коммиты начиная с `50fd220`. Основание: `docs/ИИ_ассистент_преподавателя_ТЗ_и_план.md`. Выполнены этап 0 (частично), этап 1, этап 5 и этап 2 плана; порядок изменён по решению заказчика: билеты сделаны раньше рабочих мест и голоса.

## Что изменено

### Сервер

- Новый модуль `apps/api/app/assistant.py`, роутер `/api/assistant`, подключён в `main.py`. Доступ только для преподавателя и администратора (`m.staff`), права на данные не ослабляются: ученики, билеты и рабочие места читаются через те же функции и проверки `m.visible`, что и на обычных страницах.
- `POST /api/assistant/interpret {text, context:{page}, dialog?:{intent, slots}}` → `{intent, slots, missing, candidates, preview, confirm_required, confirm_token, action, links}`. Разбор только правилами: нормализация (ё→е, регистр), регулярные выражения по каталогу команд. Намерения: `open_page` (журнал, проверка работ, рабочие места, режимы, студенты, аналитика, билеты, минивопросы, занятия), `show_reviews`, `find_last_attempt`, `student_profile`, `who_online` и «кто не в сети», `where_student`, `help`, `close`, `create_ticket`, `edit_ticket`, `unknown`. Предохранители: отрицания («не надо», «пока не», «потом») и вопросы («можно ли», «умеешь ли») дают «Понял, ничего не делаю».
- Разрешение ученика `resolve_students`: среди видимых студентов по точному слову, затем по основе слова, затем по расстоянию Левенштейна (1 для коротких слов, 2 для длинных). Ноль совпадений — «не нашёл», несколько — список кандидатов, нет имени — вопрос «Какого ученика найти?».
- Билеты, модуль `apps/api/app/assistant_tickets.py`:
  - `create_ticket`: правила извлекают из фразы службу (по имени, псевдониму «пожарная», «103»), происшествие (после «про», «о»), режим (112 или ДДС), сложность («на 3 звезды», «простой», «сложный»), пострадавших (нет, неизвестно, число, в том числе «двое», «трое») и признаки происшествия из классификатора («на улице», «открытое пламя»). Происшествие проверяется по тегам служб и классификатору (поиск в Python, так как `lower()` в SQLite не обрабатывает кириллицу); при нескольких вариантах — выбор, при общих темах вроде «пострадавшие» — отказ с подсказкой. Недостающее собирается слот-формой по одному вопросу с кнопками. Если правила не нашли происшествие, локальная модель извлекает только его; при недоступности модели ассистент задаёт обычные вопросы.
  - Разбор командой ведёт отдельная модель ассистента (`local_ai/engine.py`, `assistant_model`, по умолчанию Qwen3 0,6B, если файл есть; иначе основная), генерация билета остаётся на основной модели.
  - Подтверждение: `confirm_token` — HMAC от пользователя, намерения и слотов, срок 10 минут; подмена слотов, чужой пользователь или истечение отклоняются. `POST /api/assistant/execute {intent, slots, confirm_token}` вызывает мастер `/api/ai/wizard` и `save_ticket` напрямую под тем же пользователем.
  - Создание в два подтверждения: после генерации ассистент показывает название, описание, службы, сложность и норматив черновика; черновик ждёт на сервере 10 минут под своим id и сохраняется намерением `save_ticket` ровно один раз.
  - `edit_ticket`: билет по номеру или словам названия (выбор при неоднозначности); простые поля (сложность, название, норматив, описание, своя служба, получатели, пострадавшие) меняются новой версией; критерии, контакты, события и карточка открывают редактор на нужной вкладке через `?section=`.
  - В тестовом каталоге из двух билетов создание отклоняется заранее с понятным сообщением.
- Аудит: `assistant_command` (текст, намерение, страница, id ученика, попытки, билета, поля) на каждую команду, `assistant_executed` на каждое выполнение.
- Голос (этап 2): `POST /api/voice/transcribe {audio}` в `apps/api/app/voice.py` — распознавание на сервере для браузера без нативного моста, только staff, тот же лимит длины, что у моста (`VoiceRuntime.transcribe`), ошибки голосового модуля словами (503). Перед разбором `assistant.clean_speech` снимает хвостовую пунктуацию и расклеивает типичные склейки Whisper («подключениек» → «подключение к»).

### Клиент

- `apps/web/src/assistant.tsx`, стили `assistant.css`. Кнопка «ассистент» в шапке `ArmConsole` для преподавателя и администратора, горячая клавиша Ctrl+Space. Окно на `ArmDialog`: лента сообщений, подсказки («Что умеешь?», «Журнал», «Проверить работы», «Кто сейчас в классе?», «Новый билет»), кнопки вариантов для вопросов слот-формы, список кандидатов, ссылки в ответах (карточка работы, проверка работ, рабочие места, студенты, билет).
- Карточки подтверждения: «Выполнить / Изменить / Открыть в мастере / Отмена» для команды, «Сохранить / Сгенерировать заново / Отмена» для черновика, «Повторить» после ошибки и «Составить заново» после истечения токена. В карточке показаны модель, устройство, ожидаемое время и занятость нейросети.
- Поле ввода многострочное с ограничением высоты: Enter отправляет, Shift+Enter переносит строку. История последних 10 команд в localStorage: стрелки ↑/↓ и список «История команд». Лента и открытый диалог сохраняются при закрытии окна, есть «Очистить ленту».
- Этап 0: фильтры `/reviews` (ученик, состояние) перенесены в URL; редактор билета читает `?section=`; `DraftWizard` получил проп `initial`, страница билетов открывает мастер с предзаполненной формой из состояния навигации.
- Голос (этап 2): `record` и `MicButton` вынесены в экспорт `voice.tsx`, у `record` появился параметр `transcribe` (мост или серверный маршрут). Источник выбирается на клиенте: есть мост — мост; нет моста, но `/api/voice/settings` показывает установленный модуль — сервер; иначе микрофон отключён с подсказкой «Голосовой ввод доступен в приложении Windows или на ПК сервера». Запись идёт, пока кнопка микрофона удерживается (мышь, палец или клавиши Space/Enter на кнопке), отпускание отправляет фразу на распознавание; нажатие короче 0,4 с считается случайным и отбрасывается без распознавания (`stop(true)` у `record`); предел записи 15 с. Состояния «Говорите. Отпустите кнопку, чтобы отправить», «Распознаём…», «Распознано: …». Распознанный текст сразу отправляется в interpret; при `unknown` остаётся в поле для правки без действия; записи короче 3 символов — «Речь не распознана, повторите». При открытой карточке подтверждения короткие ответы «да», «выполняй», «подтверждаю», «сохрани» нажимают «Выполнить»/«Сохранить», а «нет», «отмена», «не надо» — «Отмена», без обращения к серверу. Ctrl+Space работает так же, как удержание кнопки: пока клавиши зажаты, идёт запись (окно открывается при необходимости), отпускание Space или Ctrl отправляет фразу; без микрофона просто открывает окно. Ошибки getUserMedia (нет HTTPS, запрет доступа, нет микрофона) показываются словами.

## Запуск

Для проверки из исходников: `python run.py`, вход преподавателем, кнопка «ассистент» или Ctrl+Space. Для генерации билета нужны файлы моделей в `local_ai/models` и среда выполнения в `local_ai/runtime` (в установленном приложении лежат в `local_ai` рядом с EXE). Новые билеты видны только при полном каталоге: `TRAINING_CATALOG=full`.
