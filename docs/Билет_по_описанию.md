# Билет по описанию

Дата: 19 октября 2026 года. Ветка `fix-ai-voice`, после слияния ветки ассистента преподавателя (`claude/assistant-ui-ux-653bc2`, `claude/elated-yalow-68c05b`).

## Где найти

Преподаватель: Билеты → «Создать билет по описанию» (рядом с «Создать билет с помощью ИИ»).
В окне одно поле: учитель описывает происшествие своими словами, например «Пожар в школе на улице Хачатуряна, дом 7, двое пострадавших, для оператора 112, сложность 4». Ctrl+Enter или «Создать черновик» запускает генерацию.

Предпросмотр показывает черновик до сохранения:
- редактируемое название;
- происшествие, кого обучаем, своя служба, получатели, сложность с причиной, пострадавшие, адрес, объект, заявитель, сообщение;
- у каждого поля пометка источника: «из описания», «ближайший тип», «выбрано вами», «случайно», «подобрано», «по умолчанию», «написано моделью», «шаблон»;
- предупреждения: тип выбран ближайший или случайно, модель не ответила;
- если точного типа нет, список ближайших типов: выбор другого пересобирает черновик с ним;
- кнопки «Изменить описание», «Сгенерировать заново», «Уточнить в мастере» (открывает мастер на 4 шага с собранными фактами: служба, происшествие, режим, сложность, пострадавшие, признаки, названный адрес), «Открыть в редакторе» (сохраняет черновик, как мастер).

## Как работает

Маршрут `POST /api/ai/prompt {prompt, incident_type?}` в `apps/api/app/prompt_ticket.py`, только для преподавателя и администратора.

1. Правила (`parse_create` ассистента и свои): сложность, режим, пострадавшие и их число, служба, адрес, заявитель после «звонит/заявитель/очевидец», объект (школа, магазин, больница…), животные.
2. Один вызов основной модели (`runtime.complete_pre`, группа настроек `pre`) с JSON-схемой: происшествие, служба, режим, пострадавшие, сложность, улица, дом, заявитель, объект, описание очевидца. Поле модели принимается, только если о нём есть слова в тексте учителя: имя и улица должны встречаться в описании, служба — называться, режим/сложность/животные — упоминаться. Фразы модели о пострадавших убираются из описания: сведения о них мастер добавляет сам. Правила важнее модели.
3. Тип происшествия: точное совпадение с тегом службы или классификатором → «из описания»; иначе ранжирование всех тегов и типов классификатора по словам описания (слова названия без совпадения снижают оценку) → «ближайший тип» и до 8 вариантов; без совпадений → случайный из знакомых (пожар, задымление, ДТП, травма, правонарушение, лифт, вода).
4. Пропуски: адрес, заявитель, телефон, подъезд — случайно из таблицы улиц Москвы; пострадавшие — «пока неизвестно»; режим — ДДС; своя служба — владелец тега или подбор по фактам; сложность — расчёт `assess_wizard`.
5. Черновик строит `scenario_wizard.build_draft` — тот же код, что у мастера. Готовое описание из запроса передаётся как есть; если его нет, модель переписывает слова учителя (без служебных фраз про звёзды, режим, адрес) или шаблон сцены. Для ДДС модель пишет доклады бригады, при ошибке — шаблоны.
6. Ответ: `{data: TicketData, meta: {model…, sources, slots, candidates, warnings}}`. Аудит `prompt_draft_generated` с текстом запроса (до 300 символов) и источниками полей.

Без модели (файлы не найдены, процесс не стартовал) билет всё равно собирается по правилам, описание — из слов учителя или шаблона, предупреждение показывается в предпросмотре. Занятая модель возвращает 503 с просьбой повторить.

Мастер `/api/ai/wizard` после выноса `build_draft` работает как раньше.

## Проверено

- `pytest apps/api/tests`: 252 пройдено, из них 10 в `test_prompt_ticket.py`: заданные факты сохраняются и билет публикуется (112), ДДС с докладами модели, случайное заполнение пустого запроса, модель не может выдумать имя, улицу, объект и тип, ближайший тип и выбор среди вариантов, ранжирование без лишних слов, работа без модели, занятая модель, 403 для ученика, значения модели без слов в запросе не принимаются.
- `npm run build` без ошибок TypeScript.
- В браузере на реальной Qwen3 4B (CPU): «Пожар в школе…» → тип «пожар», 112, 4 звезды, двое пострадавших, адрес и объект из описания, сохранение открыло редактор с той же сложностью и режимом; «Застрял лифт…» → ближайший «Застревание в лифте», выбор «лифт» пересобрал черновик; «Уточнить в мастере» открыл мастер с той же службой, типом, сложностью и режимом; «Запах газа в подъезде…» на ширине 375 px без горизонтальной прокрутки.
- Время: все прогоны шли одновременно с фоновой озвучкой ранее созданных билетов. Два черновика пришли примерно за 60–70 секунд, третий ждал общую блокировку голосового модуля около 4 минут (у мастера так же). Отдельно без озвучки время не замерялось.

## Что не сделано

- Голосовой ассистент по-прежнему создаёт билет слот-формой; передать ему свободное описание в этот маршрут — отдельная задача.
- Очередь: генерация не обгоняет фоновую озвучку. Стоит дать запросам преподавателя приоритет над фоновой озвучкой.
- Улицы и имена для случайного заполнения — те же 5 улиц и 3 имени, что у мастера.

## Исправления после проверки длинного описания (19 октября)

Запрос: «Пожар в квартире 21 этажного здания. Пожар на 14 этаже… Есть пострадавшие 2 человека: мужчина Иван Петров… Адрес: Барселона, улица Лионелли Месси 21 А, квартира 10. По телефону обращается очевидец: Игорь Иванов Владимирович, мужчина.»

- Модель не отвечала: при запуске `run.py` из репозитория в `local_ai/` нет моделей и `llama-server`. Теперь предупреждение называет причину отказа. Для генерации из исходников задайте `LOCAL_AI_DIR` (например, папку `local_ai` установленного приложения) или положите модели в `local_ai/models` и среду в `local_ai/runtime`.
- Тип «Пожар: Бар» и «пожар: переход»: слово «бар» совпадало с «Барселона». Теперь слова до трёх букв совпадают только целиком, адрес, заявитель и пострадавшие в подборе типа не участвуют, слова первой фразы весят вдвое → «пожар: квартира».
- Адрес: «Адрес: …» разбирается на город, улицу, дом (21 А → 21А), квартиру, подъезд, этаж («на 14 этаже»). Город не Москва → район и округ пустые, предупреждение; «Москва» больше не дописывается.
- Описание: фразы об адресе, заявителе и пострадавших не попадают в сцену, «мужчина» от заявителя не остаётся; подробности после «пострадавшие:» (имена, годы рождения) дописываются к сведениям о пострадавших.
- Описание модели: убираются выдуманные «в районе Северный, округе Боровицкий» и её фразы о пострадавших (и в мастере).
- Поджог и подозреваемый направляют карточку в полицию (102). Доклады бригады получают этаж и квартиру явно; «доставлены в больницу» у не-скорой отбрасывается так же, как «госпитализируем».
- Пометка «по умолчанию» стала читаемой.
- Проверено: регрессионные тесты на этот запрос с моделью и без; с Qwen3 4B на CPU получены «пожар: квартира», Барселона, улица Лионелли Месси, дом 21А, кв. 10, этаж 14, заявитель и пострадавшие из описания.
