# Как собирается Windows-билд и где лежат нейромодели

Актуально для основного приложения **Тренажёр 112 версии 0.8.20** на 18 октября 2026 года. Это описание существующей сборки, а не инструкция к экспериментальным мини-приложениям с виртуальным телефоном. Новая сборка при подготовке этого документа не запускалась.

## Короткий ответ

- Установщик включает **веса всех моделей, доступных для выбора в основной программе**: две диалоговые Qwen, две модели озвучки и две модели распознавания речи.
- Модель `Qwen3.5-2B-Q4_K_M.gguf` есть в исходной папке проекта, но **не включена**: она отсутствует в списке моделей программы и не указана в сценариях упаковки.
- В установленном приложении модели должны лежать **рядом с `Dispetcher112.exe` в папке `local_ai`**, независимо от выбранного пользователем места установки.
- **Текущий установщик 0.8.20 имеет дефект голосового окружения.** Веса речи упакованы, но часть необходимых Python-библиотек отсутствует. Файл `qwen_runtime.pth` указывает на папку разработчика `F:/AI/Qwen3-TTS/.venv/Lib/site-packages`. На другом ПК голосовой модуль может не запуститься, а интерфейс показать «не установлена». Перенос установки в другую папку это не исправляет.
- Файлы `release/Dispetcher112-0.8.20-installer/*.exe` **и все соседние `*.bin`** составляют один многотомный установщик. Передавать один маленький EXE без BIN-файлов нельзя.

## Из чего состоит сборка

1. `scripts/build-windows.ps1` устанавливает зависимости сборки, выполняет `npm ci`, проверку TypeScript и собирает веб-интерфейс Vite.
2. `packaging/desktop.spec` через PyInstaller создаёт папку `build/desktop-dist/Dispetcher112`: приложение `Dispetcher112.exe`, его Python-библиотеки и ресурсы интерфейса. Большие локальные модели в эту папку PyInstaller не кладёт.
3. `packaging/installer.iss` через Inno Setup добавляет папку PyInstaller, исполняемые файлы `llama.cpp`, выбранные GGUF-модели, голосовой Python, модели речи, готовые короткие реплики и автономный установщик WebView2.
4. Результат пишется в `release/Dispetcher112-0.8.20-installer/`. Скрипт создаёт `SHA256SUMS.txt` для EXE и BIN-файлов. Установщик рассчитан на Windows 10/11 x64 и позволяет выбрать папку назначения.

Команда штатной сборки из корня проекта:

```powershell
& .\scripts\build-windows.ps1
```

Нужны проектная `.venv`, зависимости приложения, Node/npm, Inno Setup (`ISCC.exe`) и исходные файлы моделей. Скрипт пишет в существующие `build/`, `dist/` и `release/`; перед повторной сборкой надо учитывать сохранность прежних артефактов. Переносной вариант создаёт `scripts/build-portable.ps1` из уже собранной папки PyInstaller. Он копирует тот же фиксированный список моделей и создаёт самораспаковывающийся архив в новой папке `release/`.

| Выразительная озвучка Qwen3-TTS 1.7B | `voice/models/qwen-tts/model.safetensors` и `voice/models/qwen-tts/speech_tokenizer/model.safetensors`, плюс конфигурация и токенизатор в этих папках | 3 833 402 552 + 682 293 092 байт | Да |

Правило включения задаётся **явно файлами сборки, а не автоматическим поиском всех моделей**. Две GGUF-модели перечислены по имени в `packaging/installer.iss` и `scripts/build-portable.ps1`. Папка `local_ai/voice/models/` копируется целиком, поэтому обе TTS и обе Whisper попадают в пакет. Для Qwen3.5‑2B простого наличия файла в `local_ai/models/` недостаточно: её также нет в `MODELS` внутри `local_ai/engine.py`, поэтому пользователь не может выбрать её через настройки основного приложения. Модели SmolLM3 и наборы из отдельных телефонных прототипов тоже не входят в основной билд.

Каждая установленная копия основного приложения получает перечисленные модели, даже если конкретный компьютер использует только рабочее место или выбран только быстрый вариант. Нынешняя упаковка не создаёт разные установщики по выбранной в настройках модели. Выбор CPU/GPU и конкретной модели происходит **после установки** и меняет способ использования уже находящихся на диске файлов.

По умолчанию обычные задачи диалоговой модели используют Qwen3 4B Instruct. Настройки голоса в `local_ai/voice.py` разделены на два режима: для предварительной генерации билета выбраны Qwen3 4B Instruct и Qwen3‑TTS; для живого разговора — Qwen3 0.6B, Silero и Whisper tiny. Администратор может переключить доступные модели и CPU/GPU в настройках. Whisper base остаётся доступным вариантом распознавания. Это **логика выбора при работе**, а не логика включения файлов в установщик.

## Папки после установки

`<папка_установки>` — каталог, выбранный в установщике; по умолчанию это `%LOCALAPPDATA%\Programs\Dispetcher112`.

```text
<папка_установки>\
  Dispetcher112.exe
  _internal\                       библиотеки основного приложения PyInstaller
  local_ai\
    config.json                     исходные настройки диалоговой модели
    models\                         два упакованных GGUF
    runtime\cpu\                   llama-server для CPU
    runtime\vulkan\                llama-server для Vulkan GPU
    voice_worker.py                 отдельный процесс речи
    voice\
      runtime\python.exe            отдельный Python для TTS/STT
      runtime\Lib\site-packages\   его библиотеки — должны быть автономными
      models\                       Silero, Qwen3-TTS, Whisper base/tiny
      builtin\, fillers\           готовые записи и короткие реплики
```

При запуске `packaging/desktop_launcher.py` задаёт `LOCAL_AI_DIR=<папка_установки>\local_ai`. `local_ai/engine.py` ищет GGUF и `llama-server.exe` относительно этого каталога. `local_ai/voice.py` запускает `voice/runtime/python.exe`, передаёт ему `voice_worker.py` и `voice/models/`. Таким образом, **жёсткого пути к весам** `F:/AI/Qwen3-TTS/` в рабочей схеме нет. Он попал внутрь Python через `.pth` и используется для поиска **библиотек**, что и является ошибкой текущего пакета.

Настройки, база, логи и сгенерированный звук хранятся отдельно от файлов программы, в `%LOCALAPPDATA%\Dispetcher112` (если при запуске не задан другой каталог данных). Например, голосовой модуль сохраняет настройки в `voice-settings.json`, журнал в `voice-runtime.log` и созданные WAV-файлы в `voice-cache/`. Это **не установочные веса моделей**.

## Текущее состояние голосового Python

Исходная папка `local_ai/voice/runtime/Lib/site-packages/` содержит `qwen_runtime.pth` с одной строкой:

```text
F:/AI/Qwen3-TTS/.venv/Lib/site-packages
```

В упакованном голосовом Python нет собственной полной копии `torch`, `numpy`, `soundfile`, `transformers` и `qwen_tts`: при разработке они подхватываются из указанного внешнего окружения. Поэтому отчёт о наличии `voice/models/...` или успешная самопроверка на ПК разработчика **не доказывают**, что озвучка заработает на другом компьютере. При сбое запуска `VoiceRuntime.status()` возвращает пустой список доступных моделей, отчего интерфейс может неверно назвать упакованные веса «не установленными».

Перед выпуском следующей версии требуется положить все зависимости TTS/STT внутрь `local_ai/voice/runtime/Lib/site-packages/`, исключить этот `.pth` из пакета и проверить, что импорт и синтез работают без доступа к `F:/AI/Qwen3-TTS/`. Папка `F:/AI/Qwen3-TTS/` может быть инструментом **на машине сборки**, но не должна быть зависимостью **на машине пользователя**.

## Что проверять перед передачей билда

1. Проверить состав EXE **вместе со всеми BIN-томами** и их SHA-256 по `SHA256SUMS.txt`.
2. После установки в произвольный каталог проверить наличие двух GGUF, `silero-v5-ru.pt`, обеих частей Qwen3-TTS, `whisper-base/model.bin` и `whisper-tiny/model.bin`.
3. Проверить, что голосовой Python импортирует `torch`, `numpy`, `soundfile`, `transformers`, `qwen_tts` и `faster_whisper` **из папки установленного приложения**; в путях поиска Python не должно быть `F:/AI/Qwen3-TTS/`.
4. На ПК без каталога разработчика и без сети запустить приложение, озвучить короткую фразу через Silero и Qwen3-TTS, распознать WAV через Whisper. Проверить `voice-runtime.log`, если процесс остановился.
5. Отдельно испытать установку и голос на другом ПК. Проверка только на машине сборки недостаточна.

Проверка исправленной **отдельной папки** голосового модуля на машине разработки ранее прошла: Silero, Whisper base и Qwen3‑TTS работали из локально скопированных библиотек без внешнего пути. Это **не проверка нового установщика на другом ПК**. Штатный установщик 0.8.20 остаётся с описанным дефектом; частично подготовленные экспериментальные артефакты не являются опубликованной исправленной версией.

## Исходные файлы, определяющие поведение

- `scripts/build-windows.ps1`, `scripts/build-portable.ps1` — порядок сборки и состав переносного пакета.
- `packaging/desktop.spec`, `packaging/installer.iss`, `packaging/desktop_launcher.py` — EXE, установщик и корневая папка моделей.
- `local_ai/engine.py`, `local_ai/config.json`, `local_ai/manifest.json` — доступные диалоговые модели и модель по умолчанию.
- `local_ai/voice.py`, `local_ai/voice_worker.py` — голосовые настройки, пути моделей и запуск отдельного Python.
- `local_ai/voice/runtime/Lib/site-packages/qwen_runtime.pth` — обнаруженная зависимость от абсолютного пути разработчика.
