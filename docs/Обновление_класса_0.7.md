# Учебный класс 0.7.2

В версии 0.7.2 исправлено окно просмотра ПК: оно не открывается само, если на рабочем месте никто не вошёл. Просмотр доступен, когда ученик вошёл и включил показ экрана; кнопка «Закрыть» возвращает к классу.

Источник: поручение пользователя и «Вставленный текст.txt» от 27.09.2026. Предметные источники: только девять перечисленных пользователем файлов АРМ-112, ДДС, билетов, классификаторов и РТУ Т16Р. Репозиторные старые требования к смартфонам или серверному оборудованию не используются как ТЗ.

## Запуск

Папка `release/Dispetcher112-0.7.2`, файл `Dispetcher112.exe`. Переносить всю папку, включая `_internal` и `local_ai`. Требуется Windows x64 с Microsoft Edge WebView2 Runtime. В этой переносимой поставке установщика WebView2 нет.

На первом ПК выберите «Учебный сервер», номер рабочего места и задайте пароль. Начальные логины: admin, teacher, student, student2; пароль — заданный при настройке. В администраторе допустите собственное рабочее место и создайте персональных пользователей.

На остальных ПК выберите «Рабочее место», уникальный номер и сервер из найденного списка. Вводить адрес не нужно. Обновите сервер и клиенты до 0.7.2. Допустите их в администраторе. Для частной локальной сети Windows должна разрешать входящие подключения сервера: UDP 38765 для обнаружения и TCP 8765 для работы. Кнопка «Обновить список» повторяет поиск; недоступные и посторонние HTTP-серверы не предлагаются. Микрофон может запросить разрешение Windows/WebView2. Удобнее входить через EXE: локальный клиент обеспечивает доступ к микрофону без настройки HTTPS на учебном сервере.

Повторная настройка: «Настроить подключение.cmd». Данные и настройки — `%LOCALAPPDATA%/Dispetcher112`; база и аудио копируются перед миграцией. Существующие пароли при обновлении не заменяются.

## Реализовано

- [x] Qwen3 0.6B Q4_K_M, только CPU. Старые настройки модели 4B и GPU переводятся на новую модель. Проверены SHA-256 и настоящий запрос.
- [x] Ответ, подтверждённый преподавателем, сохраняется дополнительным образцом того же задания и критерия. Образец можно отозвать. Ручная оценка имеет приоритет.
- [x] Редактируемый справочник из 26 начальных служб. Удаление из выбора сохраняет исторические карточки.
- [x] Совместное занятие: ученики 112 передают свои карточки ученикам назначенной ДДС. Статусы ДДС возвращаются оператору 112. Повторное оповещение не создаёт дубликат.
- [x] Назначение группе, ручная отправка выбранным ФИО/ПК, адаптивная выдача и спринт по времени. Новичку выдаётся не более одной незавершённой карточки; более подготовленным — до трёх, с интервалом выдачи.
- [x] Основные вкладки преподавателя: рабочие места, режимы, билеты. Другие разделы — меню «Ещё».
- [x] Обзор экранов тренажёра, демонстрация поверх окна учеников, указатель, удалённые щелчки и ввод текста, голос преподавателя. Показ включается явно; ученик может завершить подключение. Изображения живут в оперативной памяти, не записываются в базу.
- [x] Уровни 0–4, вводное знакомство и проверка нажатий Ctrl+Enter/Alt, отдельные минивопросы. Их ответы не меняют балл карточки; время минивопроса исключается из её таймера.
- [x] Таблица результатов: ФИО, номер ПК, подтверждённый балл, среднее время, замечания к тексту, уровень. Сравнение с группой включается после накопления подтверждённых работ. Удалённая помощь помечается, такие работы не повышают самостоятельный уровень.
- [x] Словарь опечаток, правила оформления, точное сравнение улицы/дома/корпуса/строения с эталоном. Текст не исправляется молча.
- [x] Учебная панель справа от АРМ, кликабельный макет телефона по РТУ Т16Р, вывод нажатой кнопки. Теги происшествия и подбор служб по правилам билета.
- [x] Мастер билета: происшествие → признаки → пострадавшие → службы → история и предлагаемая сложность → авторская правка и публикация. Адрес и имя задаются согласованными учебными данными; модель пишет обстоятельства.
- [x] Управление пользователями, именами, группами, паролями, минивопросами и допуском/блокировкой ПК. При первом запуске выбирается сервер или клиент, номер и адрес; пароль нового сервера задаётся пользователем.

## Архитектура

`classroom.py` — присутствие, допуск ПК, разрешённое подключение и обмен сигналами; `classroom_flow.py` — выдача и совместная работа; `learning.py` — уровни, минивопросы и справочники; `answer_memory.py` — образцы; `scenario_wizard.py` — генерация; `writing.py` — текст и адрес. Модели вынесены в `classroom_models.py`, миграция — `0005_classroom.py`.

Интерфейс разделён на `classroom-client.tsx` (показ/голос), `classroom.tsx` (преподаватель), `draft-wizard.tsx`, `training-tools.tsx`, `station-login.tsx`. Первая настройка и клиентский HTTP-прокси — `packaging/classroom_setup.py`.

## Проверки

- 33 автоматических теста (в том числе пять проверок обнаружения сервера): прежние 21 и новые проверки допуска, прав управления, передачи карточки, статусов, отсутствия дубликатов, образцов, отзыва, спринта, точности адреса, минивопросов и цитат модели.
- Сборка TypeScript/Vite проходит. Два независимых клиента Edge: без ошибок JavaScript; показ экрана, курсор, щелчок и ввод в настоящее поле карточки, отметка помощи, наложение экрана преподавателя. WebRTC: соединение established/connected, получены аудиопакеты от тестового микрофона.
- Настольный клиентский прокси: авторизация, cookies, API и загрузка интерфейса.
- Миграция базы с 0004 до 0005 сохраняет существующего пользователя.
- Самопроверка собранного EXE: WebView2, локальная ИИ, 6 начальных билетов, 1283 типа, сохранение после перезапуска, резервная копия, остановка сервера.
- Реальная генерация черновика 112 моделью 0.6B: около 1,9 с на этом ПК с загрузкой, черновик сохранён. Это единичная проверка, не гарантированная скорость.

## Практические границы

Передаётся интерфейс тренажёра, а не весь рабочий стол Windows. Проверка голоса выполнена с тестовым микрофоном на одном ПК: акустику, сеть и работу 20 физических компьютеров нужно проверить в самом классе. Превью экранов обновляется примерно раз в 1,8 секунды.

В схеме сервер/клиент модель работает на сервере, по одному запросу одновременно. Распределённый запуск модели на каждом ученическом CPU этой поставкой не реализован. Веса модели не дообучаются: пополняется библиотека одобренных ответов.

0.6B может ошибаться и при наличии эталона. Проверка ИИ предварительная, преподаватель утверждает итог. Несовпадающая цитата скрывается с предупреждением; ошибка формата не становится ошибкой ученика. Словарь и правила замечают опечатки и оформление, но не заменяют полноценную грамматическую экспертизу.

Получателей задаёт автор билета; официальная городская маршрутизация не подключена. В совместном режиме ДДС получает карточку и учебный типовой процесс бригады. Макет телефона пока не осуществляет реальные звонки. Черновики и исходные демонстрационные билеты требуют предметной проверки преподавателем.

## Изменения 0.7.1

Окно настройки и запуска оформлено в общей палитре тренажёра. Поля пароля видны только при создании нового сервера. Адрес заменён списком обнаруженных и проверенных учебных серверов; сохранённый сервер также проверяется при повторной настройке. Иконка 112 установлена для EXE, окна настройки и основного окна. Поиск вынесен в `packaging/lan_discovery.py`, стили — в `packaging/desktop_style.py`. Визуально проверены оба состояния окна, тесты UDP/HTTP поиска проходят. Физическое обнаружение между разными ПК зависит от разрешений локальной сети Windows.
