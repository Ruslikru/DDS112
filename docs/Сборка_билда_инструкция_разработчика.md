# Как собрать билд, чтобы голос работал на любом ПК

Инструкция для разработчика, который собирает установщик и переносную версию
на своём ПК сборки. Составлена 18 октября 2026 года по итогам разбора
[ошибки голосового модуля](Голос_автономный_runtime_2026-10-18.md).
Общее устройство сборки и список моделей описаны в
[Сборка_и_размещение_нейромоделей_0.8.20.md](Сборка_и_размещение_нейромоделей_0.8.20.md).

## Что было не так

В установщике 0.8.20 встроенный голосовой Python (`local_ai\voice\runtime`) не
содержал своих библиотек numpy, torch, torchaudio, soundfile, transformers и
qwen-tts. Вместо них в `Lib\site-packages\qwen_runtime.pth` был записан путь
к вашему окружению `F:/AI/Qwen3-TTS/.venv/Lib/site-packages`.

У вас всё работало, потому что этот путь существует. На любом другом ПК голосовой
процесс падает с `ModuleNotFoundError: No module named 'numpy'`. Не работают
озвучка Qwen3-TTS и Silero и распознавание Whisper; очередь голосовых сообщений
останавливается на числе заранее записанных реплик (например, 21/127).

**Веса моделей в установщике были в порядке.** Не хватало только библиотек.

## Главное правило

Голосовой Python в `local_ai\voice\runtime` должен быть **автономным**:
всё, что импортирует `local_ai\voice_worker.py`, лежит в его собственной папке
`Lib\site-packages`. Никаких `.pth` с путями на `F:`, в другие venv или
в системный Python.

Список библиотек и их версий берётся только из
`local_ai\voice-requirements.lock.txt`. Если нужна другая версия пакета,
измените lock-файл и заново выполните подготовку (шаг 2), а не ставьте пакет
в `F:\AI\Qwen3-TTS\.venv`.

## Что нужно на ПК сборки

- Актуальная версия репозитория, в которой есть `scripts\prepare-voice-runtime.ps1`
  и `scripts\check_voice_runtime.py`.
- Всё, что требовалось раньше: `.venv` проекта, Node.js и npm, Inno Setup
  (`ISCC.exe`), для переносной версии — 7-Zip. Файлы `local_ai`, которых
  нет в Git: GGUF-модели, `runtime\cpu`, `runtime\vulkan`, `voice\runtime`,
  `voice\models`, `voice\builtin`, `voice\fillers`,
  `downloads\MicrosoftEdgeWebView2RuntimeInstallerX64.exe`.
- **Интернет для шага 2** (один раз). Скачивается около 3–4 ГБ, в основном
  torch с CUDA 12.8 с `download.pytorch.org`, остальное с PyPI.
- Свободное место: после подготовки голосовой runtime занимает около 5,3 ГБ
  (замерено на исправленной установленной копии). Установщик станет больше
  на несколько гигабайт, добавятся BIN-тома.

## Порядок сборки

### 1. Обновить репозиторий

```powershell
git pull
```

Убедитесь, что появились оба скрипта из списка выше.

### 2. Сделать голосовой runtime автономным

Из корня проекта:

```powershell
.\scripts\prepare-voice-runtime.ps1
```

Скрипт работает с `local_ai\voice\runtime` проекта и делает следующее:

1. Удаляет `.pth`-файлы с путями за пределами runtime (ваш `qwen_runtime.pth`)
   и пишет в консоль, что удалил.
2. Удаляет pip из runtime и ставит его заново через `ensurepip`. В установленной
   копии 0.8.20 лежали файлы двух версий сразу (`pip-24.0` и `pip-26.1.2`), и pip
   падал с `ImportError`. Переустановка убирает такую смесь, если она есть.
3. На время установки переименовывает маркер `Lib\EXTERNALLY-MANAGED`.
   Runtime — копия Python от uv, и без этого pip отказывается ставить пакеты.
   После установки маркер возвращается на место.
4. Ставит все пакеты из `local_ai\voice-requirements.lock.txt` (`--no-deps`,
   точные версии) прямо в `local_ai\voice\runtime\Lib\site-packages`.
5. Запускает проверку `check_voice_runtime.py`.

Успешный результат — последняя строка:

```text
Voice runtime is self-contained: D:\...\local_ai\voice\runtime
```

Предупреждения `SoX could not be found!` и
`flash-attn is not installed` при проверке — это нормально, на синтез они не
влияют.

Шаг 2 нужен один раз и затем после каждого изменения lock-файла или замены
папки `voice\runtime`. Повторный запуск безопасен.

### 3. Собрать установщик

```powershell
.\scripts\build-windows.ps1 -InnoCompiler "C:\Program Files (x86)\Inno Setup 6\ISCC.exe"
```

Перед вызовом Inno Setup скрипт теперь сам запускает `check_voice_runtime.py`
встроенным голосовым Python. Если runtime снова зависит от внешних путей или
в нём не хватает модулей, сборка остановится с сообщением:

```text
Voice runtime is not self-contained: run scripts/prepare-voice-runtime.ps1
```

Проверка срабатывает и на вашем ПК, хотя диск F: у вас есть: она ищет любой путь
за пределами runtime, а не только несуществующий.

Перед выпуском поднимите версию в `packaging\installer.iss`
(`#define AppVersion "0.8.21"`). Так исправленный установщик не перепутать
с 0.8.20.

### 4. Собрать переносную версию (если нужна)

```powershell
.\scripts\build-portable.ps1 -OutputSuffix -r6
```

Здесь проверка запускается на уже скопированной папке, до упаковки в 7z.
Папка и архив с таким именем не должны существовать заранее.

### 5. Проверить билд не на своём ПК

Проверка на ПК сборки недостаточна: именно так ошибка 0.8.20 и прошла.

1. Перенесите на другой компьютер EXE установщика **вместе со всеми BIN-томами**
   и `SHA256SUMS.txt`, сверьте контрольные суммы.
2. Установите и запустите «Запустить на одном ПК».
3. Дождитесь, пока индикатор «Генерируются голосовые сообщения» дойдёт до конца
   (N из N). Если в списке есть упавшие задания, проверка не пройдена.
4. Позвоните по билету и убедитесь, что реплики звучат и распознавание речи
   работает.
5. Проверьте журнал голосового модуля: в
   `%LOCALAPPDATA%\Dispetcher112\demo\runs\<последний запуск>\voice-runtime.log`
   не должно быть `ModuleNotFoundError`.

Если другого ПК нет, можно временно переименовать `F:\AI\Qwen3-TTS\.venv`
и проверить установленную сборку у себя. После проверки верните папку на место.

Быстрая проверка уже установленной копии одной командой (из корня репозитория):

```powershell
& "$env:LOCALAPPDATA\Programs\Dispetcher112\local_ai\voice\runtime\python.exe" -I .\scripts\check_voice_runtime.py
```

### 6. Заменить файлы по ссылке

Выложите новый установщик (EXE + все BIN + `SHA256SUMS.txt`) и переносную версию
вместо файлов 0.8.20 по ссылке «Прототип для проверки работы» в README.
Сейчас там, скорее всего, лежит сборка с этой ошибкой.

## Если установленная 0.8.20 уже у кого-то стоит

Переустанавливать не обязательно. На этом ПК нужен репозиторий и интернет:

```powershell
.\scripts\prepare-voice-runtime.ps1 -Runtime "$env:LOCALAPPDATA\Programs\Dispetcher112\local_ai\voice\runtime"
```

После этого перезапустите приложение. Упавшие задания в уже открытом запуске
сами не повторятся; в режиме одного ПК каждый запуск создаёт новую базу.

## Чего не делать

- Не добавлять `.pth` с абсолютными путями в `voice\runtime\Lib\site-packages`.
- Не ставить пакеты голосового модуля в `F:\AI\Qwen3-TTS\.venv` в расчёте на то,
  что они попадут в билд. В билд попадает только `local_ai\voice\runtime`.
- Не копировать `site-packages` из другого venv поверх runtime вручную: так
  уже получилась смесь двух версий pip. Ставить только через
  `prepare-voice-runtime.ps1`.
- Не выкладывать билд, который проверен только на ПК сборки.
