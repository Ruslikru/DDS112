Рабочее локальное веб-приложение для обучения операторов 112 и диспетчеров ДДС. Сервер запускается на ПК; рабочие места подключаются к нему по локальной сети. Интернет во время занятий не нужен. Первичная установка зависимостей и Docker-образов требует интернета либо заранее подготовленных пакетов.

## Быстрый вход на подготовленном компьютере

Адрес: **http://localhost:8000**.

| Логин | Роль | Начальный пароль |
|---|---|---|
| `admin` | Администратор, доступ к аудиту | `Training112!` |
| `teacher` | Преподаватель учебной группы № 1 | `Training112!` |
| `student` | Алексей Морозов | `Training112!` |
| `student2` | Мария Соколова | `Training112!` |

Это демонстрационные учётные записи. Пароли меняются в разделе **Пользователи и группы → Сброс пароля**. Переменная `DEMO_PASSWORD` задаёт пароль только при первоначальном создании пустой базы, существующие пароли не меняет. При `SEED_DEMO=false` демоданные не создаются.

Сейчас подготовлен вариант **PostgreSQL в Docker + Python-сервер на Windows**. В базе есть пять начальных билетов и проверочный авторский билет, созданный при проверке UI. Две завершённые попытки демонстрируют результаты. Это учебные записи, не реальные обращения.

## Запуск

Из папки проекта в PowerShell:

```powershell
./scripts/start-local.ps1
```

Скрипт использует готовые `.venv` и `dist`, запускает PostgreSQL через Docker Compose и сервер на порту 8000. Он устанавливает зависимости только при их отсутствии. Docker Desktop должен быть запущен. Не запускайте второй экземпляр на уже занятом порту.

Если база уже работает, достаточно:

```powershell
./.venv/Scripts/python.exe run.py
```

Для разработки интерфейса, во втором терминале:

```powershell
npm run dev
```

Vite проксирует `/api` на порт 8000. Обновить готовую сборку после изменения UI:

```powershell
npm run build
```

После изменения Python-кода сервер нужно перезапустить. Его старт автоматически применяет миграции Alembic. Для ручного применения миграций: `./.venv/Scripts/python.exe scripts/migrate.py`.

### Установка на другом ПК

1. Установите Python 3.13+ и Node.js 24; для PostgreSQL — Docker Desktop.
2. Скопируйте `.env.example` в `.env`, задайте пароль БД и первоначальный пароль демопользователей.
3. Для PostgreSQL укажите `DATABASE_URL=postgresql+psycopg://dispetcher:ПАРОЛЬ@127.0.0.1:54329/dispetcher`. Пароль в URL должен быть URL-совместимым; удобно использовать случайные латинские буквы и цифры. `POSTGRES_PASSWORD` должен совпадать.
4. Запустите `scripts/start-local.ps1`. Первая установка скачает зависимости.

Без Docker можно оставить `DATABASE_URL=sqlite:///var/dispetcher.db`. Это отдельная база, удобная для одиночной демонстрации. Для учебной группы используйте PostgreSQL: конкурентные изменения защищаются блокировками строк.

### Полностью контейнерный запуск

Сначала остановите Python-сервер, занимающий порт 8000:

```powershell
docker compose --env-file .env -f deploy/compose.yaml up -d --build
```

Остановить контейнеры с сохранением данных:

```powershell
docker compose --env-file .env -f deploy/compose.yaml stop
```

Данные PostgreSQL находятся в Docker volume `deploy_postgres_data`, медиа контейнерного приложения — `deploy_app_data`. У Python-сервера медиа лежат в `var/media`. При переключении между способами запуска перенесите каталог медиа отдельно; база у них общая, если используется тот же Compose. Не удаляйте volumes для перезапуска приложения.

### Подключение телефона

Устройства должны быть в одной сети. На телефоне откройте `http://IPv4-адрес-ПК:8000`. Адрес ПК можно посмотреть командой `ipconfig`. Сервер слушает `0.0.0.0`; если Windows блокирует соединение, разрешите входящий TCP 8000 только для своей частной сети. Правила брандмауэра установщик автоматически не меняет. Экран телефона адаптивный; панель связи сворачивается кнопкой сверху. На другом физическом телефоне соединение ещё не проверялось.

## Экраны и роли

- **Обзор:** назначения, число попыток, средняя автоматическая оценка, ожидающие ручной проверки работы.
- **Мои задания / Назначения:** опубликованные билеты, тренировка или экзамен, самостоятельный старт или разблокировка преподавателем. Ученик может продолжить незавершённую попытку и повторить завершённую.
- **Рабочее место 112:** входящий вызов, подготовленные вопросы/ответы, карточка с адресом и классификацией, сохранение, выбор и оповещение служб, завершение разговора и работы.
- **Рабочее место ДДС:** полученная карточка, подтверждение приёма либо причина непринятия, сообщения бригады по таймеру, статусы и комментарии реагирования.
- **Билеты:** администратор создаёт, версионирует, публикует и архивирует билеты; преподаватель просматривает материал и назначает ученикам.
- **Редактор:** несколько заданий, режимы, исходная карточка, эталон, вопросы, ответы, MP3/WAV, сообщения бригады, критерии и веса.
- **Пользователи и группы:** создание учеников, преподавателей и администраторов, группы с ответственным преподавателем, блокировка, смена пароля, отдельное право аудита. Преподаватель видит свою группу.
- **Результаты:** автоматический разбор, ручная оценка свободного текста с обязательным пояснением, история пересмотра, статистика ошибочных критериев по категориям.
- **Журнал событий:** действия сервера, команды попыток, входы, изменения данных, переходы и нажатия кнопок интерфейса. Доступ — только по отдельному праву.
- **Система:** состояние базы и справочника, ограничения и сведения об эксплуатации.

Рабочая карточка воспроизводит основные группы полей, серые поверхности, верхние телефоны, две колонки и нижние служебные панели из S5/S6. Это функциональное воспроизведение учебного подмножества, а не полная копия всех возможностей боевого АРМ. Учебные кабинеты и редактор — собственные экраны приложения.

## Проверка карточек

Эталоны хранятся на сервере в версии задания. Ученик не получает ответы, рубрику и будущие сообщения до завершения попытки.

Критерии: значение поля; заданный вопрос; оповещённая служба; зарегистрированный статус ДДС; норматив времени; ручная содержательная проверка. Строковые значения сравниваются без регистра, различия `ё/е`, пробелов и базовой пунктуации. Семантического анализа текста нет. Для адреса со свободной формулировкой, описания и обоснования отказа применяйте ручную проверку.

Балл = доля набранного веса среди проверенных критериев × 100. Пока есть ручные критерии, балл предварительный и зачёт не выставляется. После проверки требуется не менее 70% и отсутствие критических ошибок. Проверка оповещения по одному критерию подтверждает наличие указанной службы; лишние службы автоматически не штрафуются — при необходимости добавьте ручной критерий обоснованности направления.

Учебные билеты адаптированы из исходных материалов. Во вложениях нет полного утверждённого набора эталонов. Преподаватель должен проверить начальные рубрики перед использованием для аттестации. Справочник содержит **1 283 типа** из основной XLSX; сложные условные правила маршрутизации таблицы не превращены автоматически в действующие правила.

Таблицы: `users`, `groups`, `sessions`, `tickets`, `ticket_versions`, `assignments`, `attempts`, `attempt_events`, `scheduled_events`, `audit_events`, `media_assets`, `classifier_types`, `alembic_version`.

Опубликованные версии не редактируются на месте. Попытка хранит собственный снимок задания. В командах используются `revision` и `command_id`: устаревшая команда отклоняется, повтор той же команды не выполняется снова. PostgreSQL сериализует изменения одной попытки. Запланированные события хранятся в БД и продолжаются после перезапуска сервера. После завершения попытки поздние события не меняют результат.

Пароли — Argon2; сессионный токен в HttpOnly cookie, в БД только его SHA-256. Изменение пароля/блокировка отзывают сеансы. Проверка прав выполняется сервером. API изменений требует заголовок `X-Requested-With`; CORS не разрешён. Аудио ученику доступно только после выдачи соответствующей реплики.

В первой реализации обновление карточки идёт запросом снимка каждые 2 секунды, назначений — каждые 5 секунд. Это осознанное упрощение первоначального проекта SSE, сохранённое в `docs/Решения_реализации.md`. React хранит локальный ввод отдельно от серверного снимка; сохранение карточки явное.

## Резервное копирование

Для текущего способа запуска (Python + PostgreSQL Compose):

```powershell
./.venv/Scripts/python.exe scripts/backup.py
./.venv/Scripts/python.exe scripts/verify_backup.py backups/ИМЯ_КОПИИ
```

Скрипт создаёт дамп БД, копирует локальные медиа и записывает SHA-256 каждого файла. `verify_backup.py` сверяет хеши, восстанавливает PostgreSQL в новую временную БД, проверяет число пользователей/попыток и удаляет только созданную временную БД. SQLite проверяется через `integrity_check`. Рабочая БД не перезаписывается.

При полностью контейнерном приложении перед резервированием перенесите актуальные медиа из контейнера в локальную папку резервной копии либо используйте отдельный архив volume. `backup.py` по умолчанию копирует `var/media`, а не Docker volume. База и аудио должны храниться и восстанавливаться вместе.

Для аварийного восстановления остановите приложение, восстановите `database.dump` командой `pg_restore` в новую пустую БД, укажите её в `DATABASE_URL`, верните каталог `media` и запустите приложение. Для SQLite укажите путь к восстановленному `database.sqlite`. Не восстанавливайте дамп поверх работающего учебного контура.

## Проверки

```powershell
npm run build
./.venv/Scripts/python.exe -m pytest apps/api/tests -q
```

Проверены полный цикл 112, ДДС с отказом и реагированием, обязательная причина отказа, предварительная и ручная оценки, разграничение учеников и ролей, неизменность версий, отложенный старт преподавателем, идемпотентность и конфликт ревизий, загрузка WAV и закрытый доступ к нему. Проверены сборка Docker и восстановление PostgreSQL из резервной копии. Через браузер выполнены прохождение двух режимов и создание/публикация авторского билета; просмотрено отображение на 1920×1080, 1280×720 и 390×844.

Не проверены реальные мобильные устройства, массовая нагрузка учебного класса и методическая корректность демоэталонов. Реальная телефония, передача карточек в боевой АРМ, VR, распознавание/синтез речи и ML в эту версию не входят.
